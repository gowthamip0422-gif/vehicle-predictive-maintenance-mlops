# Vehicle Predictive Maintenance — End-to-End ML Demo

![Python](https://img.shields.io/badge/Python-3.11-blue) ![FastAPI](https://img.shields.io/badge/API-FastAPI-green) ![Status](https://img.shields.io/badge/Data-Synthetic-orange)

A **portfolio-ready, reproducible ML engineering demonstration** that predicts simulated 30-day vehicle failure risk from six numerical telemetry features. It includes dataset generation, schema/range validation, a leakage-aware train/test split, preprocessing, model training and evaluation, an inference REST API, Docker packaging, automated tests and GitHub Actions. Optional MLflow experiment logging is supported.

> **Important:** All data and labels are **synthetically generated using a programmed risk formula**. Performance on these samples does **not** demonstrate real-world predictive accuracy, reliability, or safety. Do not use outputs for actual maintenance, warranty, or vehicle safety decisions. No Ford, customer, or proprietary information is included.

## Architecture

```text
Synthetic telemetry generator -> CSV -> validation -> train/test split
    -> median imputation -> Logistic Regression -> evaluation -> joblib artifact
                                                       |
                                                 FastAPI /predict
                                                       |
                                                   Docker image
```

## Quick start (Python 3.11 recommended)

```bash
git clone https://github.com/YOUR_USERNAME/vehicle-predictive-maintenance-mlops.git
cd vehicle-predictive-maintenance-mlops
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
python -m src.generate_data --rows 1500 --seed 42
python -m src.train
python -m pytest -q
uvicorn api.main:app --reload
```

Open **http://127.0.0.1:8000/docs** to try `/predict` in interactive Swagger UI. `GET /health` shows model artifact availability.

### Example request

```bash
curl -X POST http://127.0.0.1:8000/predict -H "Content-Type: application/json" -d '{"engine_temp_c":105,"battery_voltage":11.8,"oil_pressure_kpa":220,"mileage_km":110000,"vibration_mm_s":4.5,"vehicle_age_years":8}'
```

Example response *shape* (numbers depend on training data):

```json
{"failure_probability":0.7321,"risk_level":"HIGH","threshold":0.5,"predicted_failure":true}
```

## Features and labels

| Column | Meaning |
| --- | --- |
| `engine_temp_c` | Engine temperature (Celsius) |
| `battery_voltage` | Measured battery voltage |
| `oil_pressure_kpa` | Oil pressure (kilopascals) |
| `mileage_km` | Distance traveled |
| `vibration_mm_s` | Vibration amplitude in mm/s |
| `vehicle_age_years` | Age in years |
| `failure_next_30_days` | **Artificial label**, generated by synthetic risk rule |

The generator is seeded for reproducibility; columns have basic bounds checking. Data cleaning uses a `SimpleImputer` inside the training pipeline, fitted only on training data to avoid train-test leakage. Stratified holdout split is 75% train / 25% test. Evaluation reports ROC-AUC, average precision, precision, recall, and F1. Results appear in `artifacts/metrics.json` after training.

## Docker

First run `python -m src.train` to generate the model artifact, then:

```bash
docker build -t vehicle-maintenance-demo .
docker run --rm -p 8000:8000 vehicle-maintenance-demo
```

The trained `artifacts/model.joblib` file is deliberately ignored by Git and must be generated locally or in CI before building the container. Only load trusted model files; Python pickle/joblib artifacts are unsafe when obtained from untrusted sources.

## Optional experiment tracking

```bash
pip install -r requirements-mlflow.txt
python -m src.train --mlflow
mlflow ui
```

MLflow logs the run metrics and selected parameters locally. MLflow is *optional*, not needed for the basic demo.

## Continuous integration

GitHub Actions (`.github/workflows/ci.yml`) installs the developer dependencies, executes the tests, and smoke-trains the model on the committed synthetic dataset. A green CI check means tests passed, not that model accuracy has been validated on real vehicles.

## Suggested extensions

- Connect to **public** automotive or industrial maintenance data with legitimately available labels and document licenses.
- Add time-based or vehicle-grouped splits to prevent leakage from correlated real telemetry observations.
- Compare calibrated XGBoost and baseline models; tune alert thresholds based on operational costs.
- Add structured logging, drift reporting, and deployment manifests for Google Cloud Run.
- Add privacy/security review before ingesting any actual telemetry; avoid storing VIN/PII in public GitHub repos.
